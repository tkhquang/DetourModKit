# Input subsystem design

This note explains the input subsystem. Rulebook entries with the same `[B-nn]` IDs live in [AGENTS.md](../../AGENTS.md).

## Concurrency model

### input::Input

`mutex` for lifecycle, `atomic<shared_ptr<detail::InputPoller>>` for reads; `instance()` publishes an inert singleton (null pimpl, every operation fails closed) when first-use allocation fails, keeping the function-local static so `~Input` still runs the bare-`FreeLibrary` teardown; each started poller precommits a self-keepalive before publication and clears it only after a clean join and rundown, so loader-lock, failed-join, or failed-reaper paths retain the complete owner without allocating; `shutdown()` reached from a binding callback requests stop, publishes not-running, and hands its external reference to the off-thread reaper (`src/internal/lifecycle_reaper.hpp`), which invokes shutdown while the owner remains alive, then releases it only after the join, detour uninstall, and final `on_state_change(false)` complete -- an asynchronous contract documented on the method

Hot-path mechanism: `atomic<shared_ptr<detail::InputPoller>>` acquire-load, then the engine's `shared_lock` + relaxed load (not lock-free)

### detail::InputPoller

Atomic `m_active_states[]` array; the poll thread re-reserves its deferred-callback staging vector to the live binding count each cycle and stages it under one catch, so a runtime binding growth past the startup reserve cannot reallocate-then-throw out of the `jthread` body. The cycle is a transaction: each staged edge carries its own `m_active_states` transition and the whole batch is committed by a non-throwing store loop after the pass, the drained wheel backlog is rolled back, and the accumulated consume masks are cleared, so a failed pass owes no callback whose state it already consumed and the next cycle re-derives every such edge from the unchanged physical input, with no physical release and repress needed. The derived name/modifier caches rebuild build-then-swap; a rebuild driven by a flag-only change (`set_consume`) retains those caches on allocation failure instead of clearing an index that still describes the binding set, but still disarms gamepad consume suppression, because the flag change may have been a retirement and a retained rule list would outlive its binding. The `input::BindingGuard` owns a per-binding teardown gate (`src/internal/input_binding_gate.hpp`): a `HoldGate` for a hold combo, a `PressGate` for a press combo. Each gate runs the consumer callback OUTSIDE its `std::mutex`, bracketed by an in-flight count that mutex protects, so the control-plane `release()` runs down any in-flight delivery before returning; a self-release from inside the callback defers its balancing edge to that delivery's unwind when that gate has a delivery in flight, or runs the edge inline when it has none. A repeated depth-zero guard release waits for a claimant already running a balancing edge or callable disposal, while retirement waits only to its deadline and refuses if the gate remains claimed. Those waits run through consumer code; what the unlocked callback buys is that no wait chain CLOSES on the thread running it, since the delivery-depth escape is per-thread. That escape has two mechanisms because its two callers differ in what they may do when recording fails: an ordinary delivery is marked by a reserved-TLS depth and is REFUSED outright when the depth cannot be stored, while teardown consumer code -- a hold's balancing edge, and retirement's edge plus the destruction of the retired callable's captures -- cannot be declined and therefore carries a `MandatoryDeliveryScope`, which additionally records the calling thread in an intrusive registry of stack-local nodes behind a statically initialized SRW lock. That registration allocates nothing, throws nothing, nests, holds its lock only across pointer surgery so no consumer runs under it, and is keyed by native thread id. Both halves are load bearing: without the registry, two threads each inside a teardown callback that releases the other's gate read as depth-zero control plane and each waits on the other's claim; widening it to a process-wide marker instead lets an unrelated control-plane release skip the rundown its public contract promises. The per-gate `teardown_owner` stays as the same-gate recursion guard and is not a substitute for either mechanism. A cancelled hold delivers exactly one balancing `on_state_change(false)` and never a stale `true` after it, and the `HoldGate` reference-counts the N exploded entries of a multi-combo hold so overlapping combos forward only the aggregate held/released transitions

Hot-path mechanism: `shared_lock` (uncontended SRWLOCK reader) guarding the `m_active_states` pointer swap + `memory_order_relaxed` load per binding; keyboard/mouse reads route through a poll-thread-private per-cycle `KeyStateCache` so each distinct VK gets one coherent `GetAsyncKeyState` sample per cycle, not one call per binding reference

### InputIntercept

File-scope atomics shared between the poll thread and the game's threads (XInput callers, window message thread); owns its safetyhook InlineHooks directly (not via a DMK Hook handle) because the poll thread reads the trampoline and the hook lifetime is coupled to the poll thread; consume-until-release latch and wheel-pulse state are poll-thread-private; `install_xinput` takes both keepalives and constructs the never-destroyed retention cell before any prologue is patched, contains allocator/create/toggle exceptions, and reconciles toggles through `hook_patch_witness.hpp`; complete pair coverage is published only after a FINAL witness reads both prologues back immediately before the store that makes masking possible, never on the strength of the arm results alone, so a member a competing writer restored during the other member's arm window degrades the pair instead of masking one entry point while the other bypasses; the same witness runs on every maintenance call rather than short-circuiting on the published flag, so a post-publication loss is detected rather than hidden; degradation is symmetric and fail-open (either member can be the missing one, both detours go pass-through, both forwarding chains stay published for already-admitted callers) and recovery re-arms the missing member through that member's OWN existing hook object, never by layering a new hook over a prologue the pair already patched; teardown retires and drains, classifies both raw hooks before either restore, and frees only after both witness Original, otherwise moving the pair and keepalives into the reserved cell so a newer layer and its original chain stay callable; WndProc removal adopts the procedure its exchange actually displaced and compensates when a foreign subclass lands after observation; teardown is skipped under loader lock

Hot-path mechanism: Lock-free atomic loads in each detour; allocation-free, non-throwing detour bodies

## Rules

### [B-25]

The raw wheel counter saturates at `MAX_WHEEL_NOTCHES` at its write site. `InterceptWndProcTest.WheelCounterSaturatesWhenNotDrained` checks that mechanism when its window fixture is available. A skip does not qualify as release evidence under `[B-99]`.

### [B-26]

The per-direction wheel-consume mask (`publish_wheel_consume`) and the gamepad reactive mask both work this way: a `Ctrl+WheelUp` consume binding masks only the Up direction while Ctrl is held, never a bare WheelDown. Disarm on the arm-to-disarm transition too, not only via the TTL: when the last consume binding is removed (or focus / the controller is lost) the poll loop must publish an empty mask on the next cycle, or the game stays masked until the deadline lapses (~2 s). The wheel path publishes its mask every cycle; the gamepad path tracks a `was-armed` edge and disarms on it, because gating the whole gamepad publish on `m_has_consume_gamepad_bindings` alone would skip the disarm exactly when that flag flips false on removal. The TTL only self-heals a poll thread that stopped running: a loop still cycling refreshes the deadline itself, so an arming condition must also be tied to the loop's ability to DELIVER what it swallows. The wheel mask is armed only for a cycle that also drained the detour's counters, because a failed cache rebuild stops the drain while the consume binding stays registered and the subclass stays installed, and an armed mask would then latch the direction away from both the game and the mod for the rest of the process.

### [B-27]

Suppression is enforced off the engine entry's `consume` flag (the poll loop's `gamepad_owned` / `wheel_owned` pass and the detour-side rules read it), NOT off the guard's callback-enable flag, so releasing the `BindingGuard` gates the callback but leaves the game deprived of the chord for the rest of the process. A consume binding's guard teardown must therefore also clear the `consume` bit and republish (through `recompute_modifier_caches_locked`), so suppression lasts exactly as long as the guard is held. Clear it by binding IDENTITY, not by name (`set_consume_by_owner` keyed on the per-registration `consume_owner`, NOT `set_consume(name, false)`): an empty name is legal but is skipped when the poller's name index is built, so a name-keyed clear silently misses an empty-name consume binding and leaves suppression armed for the process lifetime. Reach the facade from the guard's release action in a lifetime-safe way -- `input::Input` is a strict process singleton, and the action holds a `weak_ptr` to an `Impl`-owned liveness token so a guard released after that singleton's own static teardown no-ops instead of touching a destroyed `Impl`. The composed teardown runs the gate release before the consume clear, but a still-held hold's balancing `on_state_change(false)` is user code that can throw and `HoldGate::release()` invokes it unwrapped, so wrap the gate release and run the consume clear on the throw path too (then re-raise so the guard's own catch still logs); otherwise a throwing release edge strands the suppression the clear exists to lift.

### [B-29]

A multi-combo Hold (`X = A | B`) explodes into N `InputBinding` entries that all share one `HoldGate`, and the poll loop fires each entry's press/release edge independently; forwarding each raises a duplicate `on_state_change(true)` when the second combo comes down and delivers a premature `false` when the first lifts while the other is still held. `HoldGate` keeps an `active_entries` count and forwards only the 0->1 raise and the 1->0 release (a surplus false while the count is zero is swallowed so it can never go negative). A guard release on a still-held multi-combo hold still synthesizes exactly one balancing false. Any primitive shared across N-exploded entries (a gate, a consume flag, a module-ref cell) must be driven and tested with >=2 concurrent owners, never one.

### [B-30]

A `BindingGuard::release()` that only clears a flag lets an in-flight `on_press` / `on_state_change` keep running on the poll thread, so a caller that destroys captured state the instant release returns races that call. Route delivery through a per-binding gate (`PressGate` / `HoldGate` in `input_binding_gate.hpp`) that invokes the user callback OUTSIDE its mutex, bracketed by an in-flight count the mutex protects; `release()` waits that count to zero and so cannot return while a delivery is still inside consumer code. Running the callback unlocked is what keeps the wait chain off the thread that is running user code, so two bindings whose teardown callbacks release each other cannot form an ABBA cycle; do not collapse this back to holding the gate lock across the callback, with a `recursive_mutex` or otherwise. A release reached at delivery depth > 0 (a one-shot binding destroying its own guard, or one binding's callback releasing another's) must not wait at all: it marks the gate released and defers any balancing edge to the in-flight delivery's unwind, or runs that edge inline when the gate it is releasing has no delivery in flight. The promise belongs to each CALLER, not to the gate, so a teardown that finds the gate already released still waits out the claimant's consumer-code span before returning, because its own caller is equally about to destroy captured state; retirement's span includes callable disposal, while a release's ends after its balancing edge. Claim that span under the mutex at the same moment the gate is marked released: a claimant drops the mutex to wait for deliveries to drain, so an in-flight count alone leaves a window in which a second teardown reads a quiesced gate and returns early. The same claim is what makes the unload drain's retirement and a retained guard's release exclude each other in both directions. Say plainly on the public contract what that costs, because the depth escape is per-thread and so cannot break a cycle that closes across threads: a depth-0 release waits, untimed, for whatever consumer code the claimant is running, and retirement's span includes destroying the callable's captures. A caller must release a guard without holding a lock, or owning a join, that any of that code can wait on. Prefer bounding the wait wherever the caller has a deadline to give it; `retire()` has one and refuses at it, `release()` has none.

### [B-31]

`uninstall_wndproc()`'s restore removes the detour from the chain via `SetWindowLongPtrW`, but a `wndproc_detour` frame already dispatched on the window thread loads `s_prev_wndproc` at the top of the detour and forwards there; zeroing it races that in-flight frame and routes its message to `DefWindowProcW`, silently dropping e.g. WM_CLOSE / WM_ACTIVATE at every teardown. Clear only the install-state flags (`s_hwnd` / `s_wndproc_installed`); a later re-install overwrites the predecessor. Zero it only when there is genuinely no procedure to point at (the window is already destroyed).

### [B-35]

The two off-table forms reconstruct through different readers: a source-tagged token round-trips through `parse_input_name`, but a bare-hex keyboard token (`0xNN`) round-trips only through the config combo parser behind `config::bind_combos` (whose untagged-hex fallback defaults to Keyboard). `parse_input_name` returns `nullopt` for a bare-hex token by design, so a doc or test that names the keyboard round-trip must name the config parser, not `parse_input_name`.

### [B-86]

MinGW lowers `thread_local` to `__emutls_get_address`, which allocates on each thread's first touch and serializes on a process-wide mutex to do it; a detour entered from a game thread would run both inside a hooked function. Worse than either, libgcc's `emutls.c` calls `abort()` when that allocation fails, and SIGABRT is not interceptable by a catch frame, so an enclosing `noexcept` boundary contains nothing: first-touch OOM is host death, not a reportable error. Reserve a Win32 TLS index at install time and read it from the callback instead. That primitive is not infallible either -- an index past the TEB's inline slots is backed by a lazily heap-allocated expansion array, so a store can fail under memory pressure. Treat a failed store as unknown state rather than absence, and resolve that unknown where the record is read. When the record only decides whether storage stays alive, pin it: `mid_hook_adapter.hpp` counts the unrecorded entry so a rundown retains the stub instead of concluding the thread is elsewhere and freeing it. When the record answers a per-thread question another thread acts on, refuse the operation instead: the input delivery marker (`input_delivery_scope.hpp`) declines a callback whose frame it cannot record, because widening that answer to "some thread may be in a callback" would let an unrelated control-plane release skip the rundown its public contract promises. Either way the failure needs an allocation-free identity to fall back on, so use `GetCurrentThreadId` and not `std::this_thread::get_id`, whose winpthreads `pthread_self` path allocates on a foreign thread. This rule governs the mechanism, not the spelling, and the spellings are not interchangeable here: on the toolchain the presets select (`x86_64-w64-mingw32`, thread model posix), function-local `thread_local`, namespace-scope `thread_local` and `__thread` all lower to emutls, while `__declspec(thread)` is ignored with only a `-Wattributes` warning and silently degrades to a plain shared global. Source review therefore cannot establish compliance; prove it from the emitted symbols, per compiler (`scripts/check_emit_tls.py` scans the dispatcher, input-delivery marker, and routed-retention backend objects).

### [B-92]

Advancing a binding's edge state (or draining a one-shot input backlog) as each item is evaluated makes a mid-pass allocation failure destroy the callbacks it already staged while keeping the state that says they fired: the edge is consumed, never delivered, and never re-derived. Carry each item's state transition in the staged record and apply it in a non-throwing loop after the pass, still under the lock that keeps the indices stable; roll back any source the pass consumed destructively. `detail::InputPoller::poll_loop` does this for `m_active_states` and for the wheel-notch backlog, whose notches have no physical repress a user could repeat. The rule extends to anything the pass publishes from partial work: reset the accumulated consume masks on the rollback path so suppression disarms wholly rather than in an index-dependent fragment, which is the fail-open direction `[B-26]` already requires.

### [B-95]


- Require each `InputPoller` to present its nonzero owner id for every control-plane and data-plane operation.
- Serialize owner publication on the data-plane lock.
- Serialize owner revocation on the data-plane lock.
- Serialize all five data-plane operations on the data-plane lock.
- Acquire `s_intercept_mutex` before the data-plane lock.
- Authorize an operation only when the live owner matches exactly.
- Never treat an unowned layer as permission to mutate shared state.
- Clear rules before the bounded detour drain.
- Clear masks before the bounded detour drain.
- Clear gates before the bounded detour drain.
- Clear wheel counts before the bounded detour drain.
- Release the data-plane lock before that drain waits.
- Refuse every write or drain from a stale owner after revocation.

### [B-96]

A staging lease is acquired before copying a callback into poll-cycle storage and is declared before the copied `std::function` members, so reverse member destruction releases the lease only after their callable managers and captures are destroyed. The lease remains held across dispatch, including a callback refused by a later tombstone or generation advance. Registration uses the same close-and-recheck handshake: a commit admitted before the close finishes before named retirement begins, while a later registration is refused. Teardown then waits for every staged lease it could have raced; self-delivery refuses instead of waiting on its own lease.

### [B-98]

A `GetWindowLongPtrW` observation that DMK is top can become stale before `SetWindowLongPtrW`; the exchange's returned displaced procedure is the authoritative winner. Publish uninstalled only when the exchange actually displaced DMK. If it displaced a foreign subclass, immediately put that returned procedure back on top and retain DMK as the predecessor it already captured; if another writer wins the compensation gap, restore that latest returned writer rather than clobber it and keep state conservative. The same returned-predecessor rule applies on install. A pre-check alone only shrinks the race and never authorizes overwriting the slot.
